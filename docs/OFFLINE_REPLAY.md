# 离线回放与波形形态审计

入口：采集控制台右上角“离线回放 / 波形审计”，或 http://127.0.0.1:8090/replay.html 。

## 使用

1. 选择历史会话，点击“生成 / 加载回放”。首次处理需要数秒，后续相同参数命中缓存。
2. 查看雷达未带通相位位移估计、呼吸带原始 ADC、带通标准化形态比较。
3. 播放/暂停、0.5–4 倍速、5/10/20 秒窗口与拖动进度条用于逐段检查；拖动图表缩放，双击或“全段视图”恢复。图表联动。
4. 可切换自动跟踪 / 固定中心 bin、DC 补偿开关，以及 0.03–2 Hz 内的带通上下限。更改参数后重新加载；下方摘要始终显示真正已应用的参数。
5. 导出频带预览 CSV 或审计 JSON。JSON 含质量统计、标记、处理参数和来源指纹，可复核本次预览。

## 实现方案

- 复用 `ParseStage → RangeFftStage → PhaseUnwrapStage`，新增正式 CMake 目标 `radar_replay_extract`，不再依赖 build 目录中的临时实验程序。
- 始终读取会话中的 `radar.cfg` 快照，不使用当前网页 CFG 或写死历史采样率。RX0、邻域 ±1；固定 bin 指固定邻域中心，并不等于单独使用一个 FFT 点。
- 使用两路主机接收 QPC 时间；新会话以 formalWindow.start_ns（共同 T0）为零，预采集显示为负数。旧会话没有共同区间时回退到首个雷达完整帧，并明确标为旧时间基准。
- 原始图保持各自接收时间。频带比较插值到 50 Hz 显示网格，去线性趋势、三阶零相位 Butterworth 带通，再分别标准化。重复接收时间点在插值前取均值，原始图与源 CSV 不改变。
- 雷达线上帧号缺口处分段解缠（新段位移零点重置）、分段滤波并断线；过大的主机接收间隔也使滤波分段。呼吸带超量程值保留在原始图，滤波时断开，不用掩码截断到 10 位。
- 原始图的虚线标出换单元，红线标出缺帧/端点/超量程，灰线标出呼吸带阶段边界。区分正式段质量与全程（含稳定段）质量。
- 未做相关性优化、自动时移、极性翻转或 DTW。该页面用于形态初审，不把形态相似性当作同步精度或医学结论。
- 使用现有本地 uPlot，无 CDN；计算在本机完成，不上传原始数据。

## 保存与保护

源 BIN、CFG、索引和 session.json 只读。派生文件放在：

`captures/<会话>/analysis/replay-v1/<指纹>/`

包含 `radar_phase.csv`、`preview.csv`、`preview.json` 和 `processing.json`。
缓存键包含源文件大小/修改时间、CFG SHA256、提取程序与后端代码 SHA256、处理参数；源记录或参数变化会创建新缓存。文件时间/大小指纹用于缓存更新，不是全量 BIN 密码学完整性校验。

实时采集与离线计算互斥；采集中不能生成离线图，离线任务运行时不能开始采集。结束采集按钮不受离线锁影响。
仅接受 captures 下的合法会话 ID；不允许通过网页传入任意文件路径或遍历目录。

## 限制与安装

```powershell
cmake --build build --target radar_replay_extract -j 6
.\.venv\Scripts\python.exe -m pip install -r tools\capture_service\requirements-replay.txt
.\start-capture.ps1
```

- 首版最多 30000 雷达帧、300000 呼吸带样本、2000 秒显示时间范围；提取超时 180 秒。超过时明确提示，不静默截断。长时记录的按区间读取留待后续扩展。
- 仅雷达会话可用；失败会话若仍有完整雷达帧，可查看保留数据及警告；零雷达帧会话明确提示无法回放。
- 采集中或未正常写入终态的会话不进行分析。缺索引、非单调时间、BIN 大小与帧索引不匹配会报错。
- 短片段或恒定信号可能无法生成标准化频带图；原始图仍保留。滤波边缘、稳定段、距离单元切换和 DC 补偿都可能影响形态，不可用补画或时间扭曲掩盖。


回放测试覆盖：仅雷达、缺帧分段、固定 bin / DC 关闭、无效参数与路径、活动会话拒绝、BIN/索引不符、原始文件不变、缓存更新、坏质量保留、HTTP 令牌与采集/分析互斥。
实测载入已有 1500 帧双设备会话；没有启动硬件或重新采集。

共同区间新会话（syncVersion=2）以 session.json.formalWindow.start_ns 为回放零点，预采集可见为负时间，绿色虚线标出 T₀/T₁；正式呼吸带质量按 [T₀,T₁) 重算，不使用异步实时 phase 标记。旧会话继续使用雷达首帧接收时刻为零点。

## 全程与正式区间的统一口径

摘要同时列出：全程雷达/呼吸带数量与两路接收时间的总体跨度；正式区间则按 `[T0,T1)` 的原始纳秒时间戳计数，时长严格为 T1−T0。后者与采集结束时的共同区间统计一致，T1 时刻的数据不算入正式段。

“数据范围”可选择全程或正式区间。正式视图将三幅图、播放进度与当前区间 CSV 导出限定到 `[T0,T1)`；切换不重新解缠或滤波，避免因查看范围改变波形。审计 JSON 保留全程数据并记录 viewScope。

没有正式区间的旧会话只允许全程视图，不用异步 phase 标签推导共同边界；原 phase 标签的历史统计仍保留在底层审计字段。无效 T0/T1 拒绝加载。

测试：Python 回归覆盖新旧时间基准、全程/正式计数、T1 排除与非法区间；`node tools/capture_service/test_replay_scope.cjs` 验证前端范围切换、CSV 所用裁剪、缺口保留和旧记录回退。
