本仓库的“配置”并非统一的运行时配置框架，而是按设备/通道拆分的多种配置形态并存，且大量关键参数以 C++ 常量或构造函数默认值形式硬编码。具体分为以下三类：

1. AWR1843 CLI 脚本配置（文本命令文件）
- 位置：awr1843_dca1000_read/awr1843.cfg、awr1843_dca1000_read/1T1R.cfg
- 格式：TI mmWave SDK Visualizer 导出的 .cfg 脚本，每行一条 CLI 命令（如 profileCfg、frameCfg、channelCfg），以 % 开头的注释行被忽略。
- 加载方式：AWR1843Controller::initialize(configFile) 逐行读取并追加到 configCommands 向量，随后通过串口 CLI 顺序发送；遇到 sensorStart 即停止自动下发，由上层手动控制启动。
- 参数解析：parseConfigParams() 从 profileCfg / frameCfg / channelCfg 三行中抽取频率、采样率、chirp/frame 数等，计算 ConfigParams（范围分辨率、最大速度、天线数等）供后续 TLV 帧解析使用。
- 约定：同一目录下提供多套 cfg（如 1T1R vs 4Rx），通过构造函数的 configFile 参数切换。

2. DCA1000 UDP 控制通道配置（十六进制命令 + JSON 片段）
- 命令协议：UDPController.h 中以 CONFIG_HEADER="5aa5"、CONFIG_FOOTER="aaee" 为帧头尾，中间拼接 CommandCode 枚举对应的两位十六进制码、长度与 body，再整体转为字节流发送。
- 命令集：CommandCode 枚举集中定义复位、连接、FPGA 配置、录制开始/停止等指令，内部用 cmd_to_string 映射到固定十六进制串。
- JSON 片段：cf.json 仅包含一个 DCA1000Config 对象，但当前代码并未加载该文件，实际 FPGA/包配置在 main 中以硬编码十六进制字符串直接调用 _sendCMD 下发（如 CONFIG_FPGA_GEN_CMD_CODE 对应 "0600" + "01020102031e"）。
- 网络地址：目标 IP 192.168.33.180、本地 IP 192.168.33.30、端口 4096 均写死在 UDPController 成员变量中。

3. 运行期结构体参数（C++ 内联）
- RadarParams（RadarParams.h）：描述 ADC 位数、每帧 chirp 数、采样点数、RX 数量等，用于 DataParser 解交织维度，全部在 main() 中直接赋值。
- AWR1843Controller 构造函数默认参数：CLI 串口名 COM6、波特率 115200，数据串口 COM8、波特率 921600，以及 numRx=4, numTx=1 等，均为硬编码默认值。
- 主流程中的 BYTES_PER_FRAME = 1*64*256*4 同样以表达式形式内联计算。

架构与约定总结：
- 不存在统一的配置加载器、环境变量注入或命令行参数解析；每个子系统各自管理自己的“配置来源”。
- 可变的设备行为主要依赖两套外部文件：.cfg（AWR1843 全量配置脚本）和 cf.json（目前未被使用）。
- 所有网络地址、端口、魔术字、命令码均以 constexpr / 类成员常量形式固化在源码中，修改需重新编译。
- 没有发现任何 .env、application.properties、YAML/TOML 或基于 Boost.ProgramOptions / argparse 的参数解析逻辑。

开发者应遵循的规则：
- 调整 AWR1843 射频/帧参数时，优先编辑 awr1843.cfg 或 1T1R.cfg，不要直接改 C++ 默认值。
- 修改 DCA1000 网络地址、端口或新增命令时，应在 UDPController.h 中更新常量与 cmd_map，保持 header/footer 不变。
- 若希望支持运行时切换配置，建议引入统一的命令行参数解析（如 --cfg-file、--dca-ip）并在 main() 中覆盖上述硬编码默认值，同时考虑将 cf.json 接入加载逻辑。
